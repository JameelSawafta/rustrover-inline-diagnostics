# Rust Inline Diagnostics

Rust Inline Diagnostics is a plugin for **JetBrains RustRover** that displays Rust errors and warnings directly underneath the affected source code.

Instead of hovering over highlighted code to inspect a diagnostic, the message stays visible inside the editor while you work.

[JetBrains Marketplace](https://plugins.jetbrains.com/plugin/33671-rust-inline-diagnostics)

## Features

* Persistent inline Rust diagnostics
* Errors and warnings displayed underneath source lines
* Severity-aware diagnostic indicators
* Theme-aware colors for light and dark themes
* Uses RustRover's existing code analysis
* Automatically refreshes when IDE analysis completes
* Positions diagnostics near the affected code
* Limits excessively long diagnostic messages
* Supports multiple diagnostics on the same line
* No additional configuration required

## Preview

Rust diagnostics are displayed directly below the affected code:

```text
fn main() {
    let value = missing_variable;
                └─ error: cannot find value `missing_variable` in this scope
}
```

Errors, warnings, weak warnings, and informational diagnostics use different colors based on their severity and the current editor theme.

## Why Rust Inline Diagnostics?

RustRover normally highlights errors and warnings directly in the editor, but the full diagnostic message may require hovering over the affected code.

Rust Inline Diagnostics makes these messages permanently visible while editing.

This can be particularly useful when working with Rust diagnostics related to:

* Ownership
* Borrowing
* Lifetimes
* Mutability
* Type mismatches
* Missing symbols
* Trait bounds
* Compiler warnings
* IDE inspections

## Installation

### JetBrains Marketplace

1. Open **RustRover**.
2. Go to **Settings → Plugins → Marketplace**.
3. Search for **Rust Inline Diagnostics**.
4. Click **Install**.
5. Restart RustRover if prompted.
6. Open a Rust `.rs` file.

Diagnostics will automatically appear underneath affected source lines.

## Configuration

No configuration is required.

The plugin uses RustRover's existing daemon code analysis and refreshes the displayed diagnostics whenever analysis completes.

## How It Works

Rust Inline Diagnostics does not run a separate Rust compiler or language server.

Instead, it reads diagnostics already generated by the IntelliJ Platform/RustRover code analysis system.

The plugin consists of several small components.

### Diagnostic

Represents a diagnostic collected from the IDE.

Each diagnostic contains:

* Start offset
* End offset
* Diagnostic message
* Highlight severity

### DiagnosticCollector

`DiagnosticCollector` reads highlights produced by the IntelliJ daemon using `DaemonCodeAnalyzerEx`.

Diagnostics are collected from the active editor and duplicate results are removed.

### DiagnosticInlayManager

`DiagnosticInlayManager`:

* Collects diagnostics
* Groups diagnostics by source line
* Sorts them by severity
* Displays up to four diagnostics per line
* Creates editor block inlays
* Removes outdated inlays before refreshing
* Only operates on `.rs` files

Severity priority is:

```text
ERROR
WARNING
WEAK_WARNING
INFORMATION
```

### DiagnosticRenderer

`DiagnosticRenderer` renders each diagnostic inside the editor.

Examples:

```text
└─ error: mismatched types
```

```text
└─ warning: variable does not need to be mutable
```

The renderer automatically uses different colors for:

* Errors
* Warnings
* Weak warnings
* Informational diagnostics

Colors are adapted for both light and dark IDE themes.

Diagnostic text is currently limited to 160 characters to prevent extremely long messages from taking over the editor.

### DiagnosticsStartupActivity

The startup activity registers a listener with RustRover's daemon code analyzer.

Whenever code analysis finishes, open Rust editors are refreshed and their inline diagnostics are updated.

## Building From Source

### Requirements

You will need:

* JDK 25
* Git

Gradle does not need to be installed globally because the repository includes the Gradle Wrapper.

Clone the repository:

```bash
git clone https://github.com/JameelSawafta/rustrover-inline-diagnostics.git
cd rustrover-inline-diagnostics
```

### Windows

Build the plugin with:

```powershell
.\gradlew.bat clean build
```

Build the distributable plugin archive with:

```powershell
.\gradlew.bat buildPlugin
```

### Linux / macOS

```bash
./gradlew clean build
```

To create the plugin archive:

```bash
./gradlew buildPlugin
```

The generated plugin ZIP can be found under:

```text
build/distributions/
```

## Running a Development Instance

You can launch a development instance of RustRover with the plugin installed using:

### Windows

```powershell
.\gradlew.bat runIde
```

### Linux / macOS

```bash
./gradlew runIde
```

## Current Limitations

The current implementation intentionally stays lightweight.

Some current limitations include:

* Diagnostics are limited to four messages per source line.
* Diagnostic text is shortened after 160 characters.
* Diagnostics are currently displayed for Rust `.rs` editors only.
* There are currently no user-configurable appearance settings.
* Diagnostic rendering depends on diagnostics produced by the IDE's existing code analysis.
